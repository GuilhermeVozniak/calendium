> **Migration numbering:** the eight M2 phase plans were authored in parallel, so migration filenames here are provisional — at execution time use the next free number in `backend/migrations/` and update references in the affected task.

## Goal

Ship the full M2.3 AI suite on live data: Auto Drafts, Instant Reply, Ask AI with cited sources (+ persistent sidebar), live Auto Summarize, AI editing commands, Auto Labels + custom natural-language classifiers, Auto Reminders, personal voice learning, AI scheduling drafts (availability-aware), and Instant Event AI — across backend, web, desktop, and mobile, with every feature degrading gracefully when `OPENROUTER_API_KEY` is unset.

## Architecture

**Two AI execution paths, one gateway.**

1. **Interactive path** (unchanged shape, extended surface): HTTP request → `service.AIService` → `port.AI` → OpenRouter. Gains new endpoints (`POST /v1/ai/ask`, `GET /v1/mail/threads/{id}/instant-replies`, `POST /v1/ai/event-proposal`, `/v1/classifiers` CRUD) and new `AiAction` values for editing commands.
2. **Background path (new)**: a persistent **`ai_jobs` queue table** drained by a third worker loop in `cmd/worker`. Provider sync (`service/sync.go`) and draft delivery enqueue cheap job rows at ingest/send time; `service.AIJobService` claims due jobs (`FOR UPDATE SKIP LOCKED`), calls OpenRouter, and writes results (thread summaries, instant replies, provisional AI drafts, classifier routing, auto reminders, voice profiles).

**Decision — `ai_jobs` queue, not inline-at-ingest.** Inline AI calls inside `applyMailPage` were rejected: a sync pass is bounded by `perAccountTimeout` (5 min) and must stay fast; OpenRouter calls are slow (1–10 s), flaky, and metered, and an initial sync can ingest thousands of threads. A queue gives (a) sync latency isolation, (b) retry with backoff independent of sync, (c) dedup (one pending summary job per thread no matter how many messages arrive), (d) a single choke point for per-user rate limiting/cost control, and (e) trivial graceful degradation — no API key ⇒ the loop never starts and rows simply never get enqueued. The cost — results arrive seconds after ingest instead of atomically with it — is acceptable because summaries/replies/drafts are progressive enhancements over already-rendered threads.

**Decision — extend `port.AI` with structured output.** Background features need machine-parseable results (reply arrays, booleans, cited ids). Add `CompleteJSON(ctx, system, user string, out any) (model string, err error)` to `port.AI`, implemented in the OpenRouter adapter with `response_format: {"type":"json_object"}` plus fence-stripping fallback. `Complete` stays for freeform text.

**Decision — results live on existing aggregates, not new read models.** `threads.summary` + `threads.instant_replies` (jsonb) ride the `Thread` row so every existing list/get endpoint carries them with zero new queries; AI drafts are ordinary `drafts` rows flagged `ai_generated` so they appear in `ListDrafts` and are sendable through the existing pipeline; auto reminders write `threads.remind_at` through the existing reminder machinery.

**Cost controls.** (1) Feature gate: everything keys off `OPENROUTER_API_KEY` presence — `InstanceFeatures.AI` already reports it; clients hide AI surfaces when false; the worker AI loop doesn't start; interactive endpoints return 503 `ErrAIUnavailable`. (2) Per-user daily budget: `ai_usage(user_id, day, calls)` counter checked-and-incremented atomically before every OpenRouter call (interactive + background share one budget; `AI_DAILY_LIMIT`, default 300). Exhausted background jobs reschedule to the next UTC midnight; exhausted interactive calls return 429 `ErrRateLimited`. (3) Split filtering at enqueue: summary/instant-reply/auto-draft jobs are only enqueued for `important`/`vip`/`team`/`calendar` threads with a genuinely new inbound message; `news`/`social`/`other` get on-demand generation only. (4) Job dedup via partial unique index so message bursts collapse into one job.

## Tech Stack

- Backend: Go stdlib only (net/http, database/sql, encoding/json), pgx driver, hexagonal layout (`domain` → `port` → `service` → `adapter`). Testcontainers Postgres for repo tests.
- Queue: plain Postgres table + `FOR UPDATE SKIP LOCKED` claim (no new infra).
- AI gateway: OpenRouter chat-completions, `response_format json_object` for structured calls.
- Clients: `@calendium/shared` typed `ApiClient`; Next.js web + Wails desktop frontend (shadcn new-york); Expo mobile. Vitest (shared/web/desktop), Jest (mobile), Playwright e2e (web, demo mode).

func (c *Client) CompleteJSON(ctx context.Context, system, user string, out any) (string, error) {

// stripJSONFences tolerates models that wrap JSON in ```json fences.
func stripJSONFences(s string) string {
	s = strings.TrimSpace(s)
	s = strings.TrimPrefix(s, "```json")

```go
// AiJobRepo persists the background AI job queue.
type AiJobRepo interface {
	// Enqueue inserts the job; on (kind, thread_id) conflict it resets
	// run_after/locked_at so a message burst collapses into one fresh job.
	Enqueue(ctx context.Context, j domain.AiJob) error
	// ClaimDue atomically claims up to limit due jobs (run_after <= now,
	// unlocked or lock expired >10m) with FOR UPDATE SKIP LOCKED, bumping
	// attempts and locked_at. Safe under concurrent workers.
	ClaimDue(ctx context.Context, now time.Time, limit int) ([]domain.AiJob, error)
	// Complete deletes a finished job.
	Complete(ctx context.Context, id string) error
	// Fail records errMsg and re-arms the job at retryAt, or dead-letters it
	// (row deleted, error logged by caller) when retryAt is nil.
	Fail(ctx context.Context, id string, retryAt *time.Time, errMsg string) error
}
```

```go
// port/driving.go
// AIJobService drains the background AI job queue (consumed by cmd/worker).
type AIJobService interface {
	// ProcessDueAiJobs claims and executes one batch of due AI jobs.
	// It is a no-op returning nil when AI is not configured.
	ProcessDueAiJobs(ctx context.Context) error
}
```

```go
// service/ai_jobs.go (real code — the core loop)
const (
	aiJobBatch       = 20
	aiJobMaxAttempts = 4
)

type AIJobServiceDeps struct {
	Jobs          port.AiJobRepo
	Usage         port.AiUsageRepo
	Accounts      port.AccountRepo
	Threads       port.ThreadRepo
	Messages      port.MessageRepo
	Drafts        port.DraftRepo
	Labels        port.LabelRepo
	Classifiers   port.ClassifierRepo
	VoiceProfiles port.VoiceProfileRepo
	Calendar      port.CalendarService // availability for scheduling drafts / event proposals
	AI            port.AI              // nil disables the whole service
	Clock         port.Clock
	DailyLimit    int // AI_DAILY_LIMIT, default 300
	Logger        *slog.Logger
}

type AIJobService struct {
	d AIJobServiceDeps
}

var _ port.AIJobService = (*AIJobService)(nil)

func NewAIJobService(d AIJobServiceDeps) *AIJobService {
	if d.DailyLimit <= 0 {
		d.DailyLimit = 300
	}
	return &AIJobService{d: d}
}

func (s *AIJobService) ProcessDueAiJobs(ctx context.Context) error {
	if s.d.AI == nil {
		return nil // graceful degradation: no key, no work
	}
	now := s.d.Clock.Now()
	jobs, err := s.d.Jobs.ClaimDue(ctx, now, aiJobBatch)
	if err != nil {
		return err
	}
	var errs []error
	for _, j := range jobs {
		if ctx.Err() != nil {
			return ctx.Err()
		}
		if err := s.runJob(ctx, j); err != nil {
			errs = append(errs, fmt.Errorf("ai job %s (%s): %w", j.ID, j.Kind, err))
		}
	}
	return errors.Join(errs...)
}

// runJob executes one claimed job: budget check, dispatch, retry/backoff.
func (s *AIJobService) runJob(ctx context.Context, j domain.AiJob) error {
	allowed, err := s.d.Usage.IncrementAndCheck(ctx, j.UserID, s.d.Clock.Now(), s.d.DailyLimit)
	if err != nil {
		return err
	}
	if !allowed {
		// Budget exhausted: park until next UTC midnight, don't count attempt.
		next := s.d.Clock.Now().UTC().Truncate(24 * time.Hour).Add(24 * time.Hour)
		return s.d.Jobs.Fail(ctx, j.ID, &next, "daily ai budget exhausted")
	}
	err = s.dispatch(ctx, j)
	switch {
	case err == nil:
		return s.d.Jobs.Complete(ctx, j.ID)
	case errors.Is(err, domain.ErrNotFound):
		// Thread/draft vanished under the job: drop it, not an error.
		return s.d.Jobs.Complete(ctx, j.ID)
	case j.Attempts >= aiJobMaxAttempts:
		if ferr := s.d.Jobs.Fail(ctx, j.ID, nil, err.Error()); ferr != nil {
			return errors.Join(err, ferr)
		}
		return fmt.Errorf("dead-lettered after %d attempts: %w", j.Attempts, err)
	default:
		retry := s.d.Clock.Now().Add(aiJobBackoff(j.Attempts))
		if ferr := s.d.Jobs.Fail(ctx, j.ID, &retry, err.Error()); ferr != nil {
			return errors.Join(err, ferr)
		}
		return err
	}
}

func (s *AIJobService) dispatch(ctx context.Context, j domain.AiJob) error {
	switch j.Kind {
	case domain.AiJobThreadSummary:
		return s.runThreadSummary(ctx, j)
	case domain.AiJobInstantReplies:
		return s.runInstantReplies(ctx, j)
	case domain.AiJobAutoDraft:
		return s.runAutoDraft(ctx, j)
	case domain.AiJobClassify:
		return s.runClassify(ctx, j)
	case domain.AiJobReminderDetect:
		return s.runReminderDetect(ctx, j)
	case domain.AiJobVoiceProfile:
		return s.runVoiceProfile(ctx, j)
	default:
		return fmt.Errorf("unknown ai job kind %q", j.Kind)
	}
}

// aiJobBackoff: 1m, 4m, 16m, capped at 30m.
func aiJobBackoff(attempt int) time.Duration {
	d := time.Minute << uint(2*(attempt-1))
	if d <= 0 || d > 30*time.Minute {
		return 30 * time.Minute
	}
	return d
}
```
